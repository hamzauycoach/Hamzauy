# Security Policy

## Supported Versions

Security fixes are provided for the latest code on `main`.

| Version | Supported |
| ------- | --------- |
| `main`  | Yes |
| Older snapshots, forks, custom deployments | No |

## Reporting a Vulnerability

Please report security issues privately.

Do not open a public issue for vulnerabilities.

### Preferred Contact

- WhatsApp: [+20 155 740 3075](https://wa.me/201557403075)

### Alternative Contact

- GitHub Security Advisory (Repository `Security` tab -> `Report a vulnerability`)

## What to Include

Include as much of the following as possible:

- A clear description of the issue
- Affected page/file and location
- Reproduction steps
- Impact (what an attacker can do)
- Proof of concept (if available)
- Suggested fix (optional)

## Response Targets

- Initial acknowledgment: within 24 hours
- Triage and severity assessment: within 3 business days
- Fix target for critical issues: within 7 days

Actual timelines can vary depending on complexity and deployment constraints.

## Disclosure Policy

- Please allow time for investigation and remediation before public disclosure.
- After a fix is deployed, coordinated disclosure is welcome.
- Research performed in good faith will not be treated as malicious.

## Scope Notes

This repository is primarily a static website. Typical in-scope issues include:

- Cross-site scripting (XSS)
- Sensitive data exposure in client-side code
- Unsafe third-party script usage
- Security misconfiguration in delivered pages/assets

Out of scope unless a clear security impact is shown:

- Purely visual/UI bugs
- SEO/content typos
- Best-practice suggestions without exploitability
